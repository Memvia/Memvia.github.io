OpenClaw Docker 容器化部署完全指南

OpenClaw 是一款开源 AI 执行引擎，由 PSPDFKit（现 Nutrient）创始人 Peter Steinberger 开发。与传统聊天机器人不同，它能够通过自然语言指令自主规划和完成全流程任务，而不仅仅是回答问题。本教程将帮助你快速掌握 OpenClaw 的 Docker 容器化部署，实现开箱即用的 AI 助手体验。

第一部分：概念理解

1.1 什么是 OpenClaw？

OpenClaw 本质上是一个AI 执行引擎，而非简单的聊天工具。传统 AI（如 ChatGPT）是被动响应式的问题回答者，而 OpenClaw 是主动执行式的任务完成者。你可以把它理解为「AI 驱动的数字员工」，它能够：

  • 自主规划：理解复杂任务并制定执行步骤
  • 工具调用：执行代码、操作文件、浏览网页、发送消息
  • 多渠道接入：通过各种即时通讯平台与你交互
  • 本地优先：数据存储在本地，保护隐私安全

1.2 核心架构

OpenClaw 采用模块化架构，主要由以下组件构成：

组件 作用 类比
Gateway（网关） 消息入口、认证、路由、控制平面 公司前台/传达室
Agent（代理） AI 推理引擎，负责思考和决策 公司的员工
Tools（工具） 浏览器、命令行、文件操作等能力 员工的工具箱

通俗理解：Gateway 是公司的接待处，负责接收来自各个渠道（Telegram、飞书、钉钉等）的消息，并进行身份验证；Agent 是具体干活的员工，负责思考和处理任务；Tools 是员工使用的各种工具（电脑、打印机、网络浏览器等）。

1.3 为什么选择 Docker 部署？

Docker 部署为 OpenClaw 带来了显著优势：

  • 环境一致性：消除「在我机器上能运行」的问题，容器内环境与开发环境完全一致
  • 隔离性：保护主机环境，出了问题不会影响其他服务
  • 可移植性：易于在不同服务器间迁移
  • 简化依赖管理：无需在主机上安装 Node.js 等运行时
  • 沙箱支持：可使用 Docker 实现 Agent 工具的隔离执行

变量名 必填 说明

OPENCLAW_GATEWAY_PORT 否 Gateway 端口，默认 18789

OPENCLAW_HOME_VOLUME 否 Docker 命名卷，用于持久化 /home/node
OPENCLAW_SANDBOX 否 是否启用沙箱：1/true/yes/on

4.5 飞书配置（国内重点）

飞书是国内企业广泛使用的协作平台，以下是详细配置步骤：

步骤 1：创建飞书自建应用

  1. 访问 飞书开放平台
  2. 点击「创建应用」，选择「企业自建应用」
  3. 填写应用名称和描述

步骤 2：获取应用凭证

  1. 点击「凭证与权限」→「应用凭证」
  2. 获取 App ID 和 App Secret

步骤 3：配置机器人能力

  1. 点击「添加应用能力」→「机器人」
  2. 启用机器人功能

步骤 4：配置事件订阅（关键步骤）

  1. 点击「事件订阅」→「配置」
  2. 点击「添加事件」，选择 im.message.receive_v1（接收消息）
  3. 需要权限：
    • im:message:receive_as_bot - 以机器人身份接收消息
    • im:message:send_as_bot - 发送消息
    • im:chat:readonly - 读取群组信息
  4. 点击「发布」
